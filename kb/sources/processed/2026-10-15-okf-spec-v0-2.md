# Open Knowledge Format specification

- URL: https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md
- Retrieved: 2026-10-15
- Publisher: Google Cloud, `knowledge-catalog` repository. Version 0.2, which replaced v0.1 on 2026-07-24. The last change to the file was on 2026-08-21.
- Why it matters: the file format this KB's pages follow

## What it says

Notes on the parts the KB relies on, not a copy.

- A concept page is UTF-8 Markdown with YAML frontmatter between `---` lines. `type` is the only required key, and its value is any short string. `title`, `description` (one sentence), `resource` (a canonical URI) and `tags` (a list) are recommended. Producers may add keys, and readers keep keys they don't know.
- Every timestamp is an ISO 8601 date and time with an explicit UTC offset.
- `generated` records how the current content was produced, as `{ by, at }`. `by` is required, and `at` marks the content's last meaningful change.
- `verified` lists who confirmed the content against its sources, each as `{ by, at }`. One `{ by, at }` without a list is allowed and counts as a list of one. No `verified` means unverified, verified by machines only means machine-confirmed, and verified by a `human:` actor means human-reviewed.
- Actors are written `<producer>/<version>` for agents and tools, `human:<id>` for a person and `process:<id>` for an automated process. Readers judge trust by the `human:` prefix, so hand-written or human-checked content must use it.
- `status` is `draft`, `stable` or `deprecated`. A page without one is stable. `stale_after` is the instant from which a page is stale.
- `sources` lists what a page derives from. Each entry needs `resource`: a URL, a path in the bundle or a description of a scope. `id`, `title`, `author`, `usage_count` and `last_modified` are optional. `id` should be there when the body cites the source.
- A single claim is attributed with a Markdown footnote whose label is a source's `id`. Labels are keys rather than positions, so reordering the list doesn't misattribute claims.
- `index.md` is reserved. It lists a folder in headed sections of `[Title](url) - description` bullets. It has no frontmatter, except that the bundle root's may carry `okf_version`.
- `log.md` is reserved. It's a flat history under `## YYYY-MM-DD` headings, newest date first. A bold word at the start of each entry is conventional.
- Links that start with `/` resolve from the bundle root and are recommended. Plain relative links are allowed too. Readers must tolerate broken links.
- The folder layout is up to the producer. A bundle can be a folder inside a larger git repository.
- What changed from v0.1: `timestamp` gave way to `generated.at`, and the body `# Citations` list gave way to `sources`. Readers may fall back to both for v0.1 pages. Everything else is an addition.
- A bundle conforms when every page that isn't reserved has frontmatter that parses, with a non-empty `type`, and its `index.md` and `log.md` files follow their formats.
